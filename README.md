# 🌐 **پروژه `فایل‌مارکت` — فروشگاه فایل نرم‌افزار، طراحی وب سایت و محصولات مجازی**

فروشگاه اینترنتی کامل برای **فروش فایل‌های نرم‌افزاری، قالب و افزونه وب سایت، اسکریپت، فایل‌های طراحی و محصولات مجازی** ساخته‌شده با Django، به‌همراه بخش حرفه‌ای **خدمات طراحی وب سایت** (تعرفه، نمونه‌کار و دریافت درخواست پروژه).

## 🚀 راه‌اندازی سریع

```bash
pip install -r requirements.txt
cp .env.example .env            # مقادیر درگاه‌ها و کلیدها را تنظیم کنید
python manage.py migrate
python manage.py seed_demo      # داده‌های نمونه کامل + کاربران آزمایشی
python manage.py runserver
```

> **دیتابیس:** توسعه با SQLite و بدون هیچ تنظیمی اجرا می‌شود. برای تولید کافی است
> `DATABASE_URL=postgresql://user:pass@host:5432/dbname` را در `.env` بگذارید
> (درایور `psycopg` در requirements هست)؛ مهاجرت‌ها روی هر دو موتور اعمال می‌شوند.

## ⚡ اجرای یک‌کلیکی — `run.bat`

روی ویندوز کافی است فایل **`run.bat`** را دابل‌کلیک کنید (یا در cmd اجرا کنید). این اسکریپت همهٔ مراحل را خودش انجام می‌دهد:

1. پیدا کردن پایتون نصب‌شده (`py -3` و در غیر این صورت `python`)
2. ساخت محیط مجازی `.venv` (اگر نباشد)
3. نصب بسته‌ها از `requirements.txt`
4. ساخت فایل `.env` محلی با `DEBUG=True` و یک `SECRET_KEY` تصادفی (فقط اگر `.env` وجود نداشته باشد)
5. اجرای `migrate`
6. **ساخت کاربر مدیر پیش‌فرض** با دستور `create_default_admin`
7. اجرای سرور روی پورت ۸۰۰۰ و بازکردن `/admin-panel/` در مرورگر

**اطلاعات ورود پیش‌فرض:** `admin` / `admin1234`

```bat
run.bat                                  :: کاربر admin با رمز admin1234
run.bat reza My-Long-Pass-123            :: کاربر و رمز دلخواه
run.bat admin admin1234 9000             :: پورت دلخواه
run.bat admin admin1234 8000 --seed      :: همراه با داده‌های نمونه (seed_demo)
run.bat --no-browser                     :: بدون بازشدن خودکار مرورگر
```

روی لینوکس و مک معادل همین اسکریپت با نام **`run.sh`** در دسترس است:

```bash
chmod +x run.sh
./run.sh                       # یا: ./run.sh reza My-Long-Pass-123 8000 --seed
```

### ساخت/مدیریت کاربر مدیر

دستور `create_default_admin` آیدمپوتنت است: اگر کاربر وجود داشته باشد **رمز او تغییر نمی‌کند** (مگر با `--reset-password`)، فقط دسترسی مدیر/superuser را تضمین می‌کند.

```bash
python manage.py create_default_admin                                  # admin / admin1234
python manage.py create_default_admin --username reza --password My-Long-Pass-123
python manage.py create_default_admin --username admin --password New-Pass-123 --reset-password
```

- رمز باید حداقل ۸ کاراکتر باشد.
- در محیط عملیاتی (`DEBUG=False`) ساخت حساب با رمز پیش‌فرض `admin1234` **رد می‌شود**؛ رمز قوی را با `--password` یا متغیر محیطی `ADMIN_DEFAULT_PASSWORD` بدهید.
- نام کاربری/ایمیل پیش‌فرض هم با `ADMIN_DEFAULT_USERNAME` و `ADMIN_DEFAULT_EMAIL` قابل تغییر است.

**کاربران نمونه (فقط توسعه):**

| کاربر | نام کاربری | رمز عبور | توضیح |
|---|---|---|---|
| مدیر | `admin` | `admin1234` | دسترسی `/admin/` و `/admin-panel/` |
| نمونه | `demo` | `demo1234` | دارای یک سفارش پرداخت‌شده و فایل قابل دانلود |

> در محیط عملیاتی، `seed_demo` هرگز با این رمزهای شناخته‌شده حساب ایجاد نمی‌کند. پیش از اجرای آن، برای حساب‌های تازه `SEED_ADMIN_PASSWORD` و `SEED_DEMO_PASSWORD` را با رمزهای حداقل ۱۲ کاراکتری تنظیم کنید.

### 🩺 رفع `ModuleNotFoundError` (مثلاً `No module named 'django_ckeditor_5'`)

این خطا یعنی بسته‌های `requirements.txt` در **همان مفسر پایتونی** که `manage.py` را اجرا می‌کند نصب نشده‌اند — معمولاً چون `pip install -r requirements.txt` اجرا نشده، یا در محیط مجازی (venv) نصب شده‌اند اما `python manage.py` با پایتون سیستم اجرا می‌شود.

```powershell
# ویندوز (PowerShell)
cd C:\path\to\MasaiShop
py -m venv .venv
.\.venv\Scripts\Activate.ps1          # اگر اسکریپت فعال نشد: .\.venv\Scripts\activate.bat
python -m pip install --upgrade pip
python -m pip install -r requirements.txt
python -c "import sys, django_ckeditor_5; print(sys.executable)"   # باید مسیر .venv را چاپ کند
python manage.py migrate
```

```bash
# مک/لینوکس
python3 -m venv .venv && source .venv/bin/activate
python -m pip install -r requirements.txt
python manage.py migrate
```

نکته‌ها:

- همیشه از `python -m pip install ...` استفاده کنید، نه `pip install ...`؛ این‌طور مطمئن می‌شوید بسته در همان پایتونی نصب می‌شود که بعداً `manage.py` را اجرا می‌کند.
- برای دیدن اینکه کدام پایتون در حال اجراست: `python -c "import sys; print(sys.executable)"`. مسیر باید داخل `.venv` باشد.
- در PowerShell، اگر فعال‌سازی venv با خطای Execution Policy مواجه شد: `Set-ExecutionPolicy -Scope CurrentUser RemoteSigned`.
- `manage.py` اکنون پیش از استارت جنگو، بسته‌های نصب‌نشده را فهرست می‌کند و دستور نصب دقیق را با مسیر همان پایتون چاپ می‌کند. اگر محیط شما با ابزار دیگری (مثلاً Docker یا Poetry) آماده می‌شود، با `MASAISHOP_SKIP_PREFLIGHT=1` این بررسی را رد کنید.
- حداقل نسخهٔ پشتیبانی‌شدهٔ پایتون ۳.۱۰ است (پشتیبانی از ۳.۱۴ از جنگو ۵.۲.۸ به بعد؛ پروژه روی ۵.۲.۱۷ پین شده است).

### 🩺 پنجرهٔ `run.bat` باز می‌شود و **فوراً بسته** می‌شود

این مشکل تقریباً همیشه ربطی به کد پروژه ندارد و علتش **نحوهٔ ذخیرهٔ خود فایل `run.bat`** است:

| علت | نشانه | راه‌حل |
| --- | --- | --- |
| پایان‌خط **LF** (لینوکسی) به‌جای **CRLF** | cmd برچسب‌های `goto` را پیدا نمی‌کند: `The system cannot find the batch label specified` و پنجره بسته می‌شود | فایل را با پایان‌خط ویندوزی (CRLF) ذخیره کنید |
| انکودینگ **UTF-8 با BOM** | خط اول به‌شکل `´╗┐@echo off` خوانده می‌شود و خطای *not recognized* می‌دهد | فایل را **UTF-8 بدون BOM** ذخیره کنید |
| انکودینگ **ANSI/Windows-1256** | متن فارسی به هم می‌ریزد (خود اسکریپت کار می‌کند) | UTF-8 بدون BOM |

در همین مخزن، فایل `.gitattributes` اضافه شده تا `git` همیشه `*.bat` را با CRLF نگه دارد و این اتفاق تکرار نشود.

**برای دیدن پیام خطای واقعی،** فایل را دابل‌کلیک نکنید؛ یک `cmd` باز کنید و دستور زیر را بزنید تا پنجره باز بماند:

```bat
cd C:\path\to\rahsadev123
run.bat
```

از این پس خود `run.bat` هم در پایان کار (اگر سرور متوقف یا با خطا بسته شود) یک `pause` می‌زند تا پنجره بسته نشود.

> اگر فایل را با **دانلود ZIP** گرفته‌اید و مشکل ادامه دارد، از `git clone` استفاده کنید یا فایل را در Notepad++ با گزینه‌های `Edit → EOL Conversion → Windows (CRLF)` و `Encoding → UTF-8` (بدون BOM) ذخیره کنید.

### 🩺 خطای ۴۰۳ هنگام ورود: `Origin checking failed ... does not match any trusted origins`

اگر سایت را پشت پروکسی HTTPS (هاست اشتراکی، nginx، یا پیش‌نمایش آنلاین) باز می‌کنید و هنگام **ورود** به `/admin/` یا `/admin-panel/` خطای ۴۰۳ می‌گیرید، دلیلش بررسی CSRF جنگو است: مرورگر هدر `Origin` را با آدرس `https://…` می‌فرستد ولی جنگو درخواست را `http` می‌بیند.

راه‌حل: دامنهٔ واقعی سایت را در `.env` به `CSRF_TRUSTED_ORIGINS` اضافه کنید (با اسکیم و بدون اسلش انتهایی):

```bash
CSRF_TRUSTED_ORIGINS=https://example.com,https://admin.example.com
```

پس از تغییر، سرویس را ری‌استارت کنید. اگر پروکسی شما هدر `X-Forwarded-Proto: https` را ارسال می‌کند، می‌توانید به‌جای آن `SECURE_PROXY_SSL_HEADER` را در تنظیمات فعال کنید تا `request.is_secure()` درست تشخیص داده شود.

## 🖥️ پنل مدیریت

دو لایهٔ مدیریتی در پروژه وجود دارد و هر دو با هویت بصری فروشگاه (فونت وزیرمتن، پالت فیروزه‌ای، حالت شب/روز) بازطراحی شده‌اند.

### ۱) داشبورد تحلیل — `/admin-panel/`

| بخش | توضیح |
|---|---|
| شاخص‌های کلیدی | درآمد موفق، سفارش پرداخت‌شده، میانگین ارزش سفارش، کاربران جدید، دانلودها و تراکنش ناموفق — هرکدام با درصد تغییر نسبت به دورهٔ قبل |
| نمودار درآمد روزانه | نمودار ترکیبی (خط درآمد + ستون تعداد سفارش) با برچسب تاریخ شمسی |
| نمودار وضعیت سفارش‌ها | دونات به‌همراه راهنمای فارسی |
| سهم نوع محصول | درآمد هر نوع فایل (قالب، افزونه، اسکریپت، نرم‌افزار، فایل طراحی، مجازی) |
| پرفروش‌ترین فایل‌ها | رتبه‌بندی با نوار سهم و لینک مستقیم به فرم ادمین |
| عملکرد درگاه‌ها | تعداد تلاش، موفق، نرخ موفقیت و وضعیت اتصال کلیدها |
| نیازمند رسیدگی | سفارش در انتظار، تراکنش ناموفق، درخواست طراحی جدید، پیش‌نویس‌ها، موجودی روبه‌اتمام، محصول بدون فایل |
| دسترسی سریع | افزودن محصول/مقاله/بنر/کد تخفیف/پکیج/ریدایرکت با یک کلیک |
| جدول‌ها | آخرین سفارش‌ها، تراکنش‌ها، درخواست‌های طراحی، توکن‌های دانلود و مقالات |

- **فیلتر بازه زمانی:** ۷، ۳۰، ۹۰ روز و یک سال (`/admin-panel/?range=90`)؛ مقدار نامعتبر به ۳۰ روز برمی‌گردد.
- **خروجی CSV:** `/admin-panel/export/orders/?range=30` با BOM تا فارسی در اکسل درست نمایش داده شود.
- **صفحه سلامت فروشگاه:** `/admin-panel/health/` — فهرست محصولات بدون فایل، بدون تصویر، بدون توضیح سئو، لایسنس‌های روبه‌اتمام و محتوای نیمه‌تمام.
- **نمودارها آفلاین:** Chart.js 4.5.1 به‌صورت محلی در `static/js/plugins/chart.umd.min.js` قرار دارد (لایسنس MIT) و هیچ CDN خارجی صدا زده نمی‌شود.
- **حالت شب/روز:** کلید `fm-theme` با فروشگاه مشترک است، بنابراین انتخاب کاربر در هر دو بخش حفظ می‌شود.
- آمار در `dashboard/analytics.py` محاسبه می‌شود و کاملاً خواندنی است؛ همه تاریخ‌ها بر پایه منطقه زمانی `Asia/Tehran` و با برچسب شمسی.

### ۲) Django Admin — `/admin/`

- پوستهٔ اختصاصی (`static/css/fm-admin.css`) با بازنویسی همان متغیرهای CSS خود جنگو؛ کلید حالت شب/روز خود جنگو کار می‌کند.
- سربرگ، عنوان تب و فوتر ادمین نام و لوگوی **تنظیمات سایت** را نشان می‌دهند (`MasaiShop/admin_branding.py` + `core/branding.py`).
- نوار شاخص سریع بالای خانهٔ ادمین (سفارش‌ها، درآمد، محصولات، کاربران، درخواست‌ها) از برچسب `{% admin_quick_stats %}` می‌آید.
- لینک‌های سریع در هدر ادمین: داشبورد تحلیل، سلامت فروشگاه، محصول/مقاله/کد تخفیف جدید و ریدایرکت‌ها.
- امکانات مشترک ModelAdminها (`core/admin_utils.py`):
  - اکشن **خروجی CSV** با سرستون‌های فارسی و BOM (متن HTML و رابطه‌های چندبه‌چند به متن ساده تبدیل می‌شوند)
  - تاریخ شمسی در ستون‌های لیست، `date_hierarchy`، `list_select_related` و تعداد ردیف مناسب
  - `autocomplete_fields` برای فروشنده/دسته/برند/نویسنده (جست‌وجوی زنده به‌جای کشوی بلند)
  - فیلترهای بیشتر و جست‌وجوی گسترده‌تر
  - اکشن‌های دسته‌جمعی: انتشار/پیش‌نویس و ویژه‌کردن محصولات، انتشار مقالات، ثبت تماس و پایان درخواست‌های طراحی
  - در فرم سفارش، اقلام به‌صورت inline **فقط‌خواندنی** نمایش داده می‌شوند تا مبالغ دستی تغییر نکنند.

## 🧩 بخش‌های فروشگاه

`فروش فایل‌ها`
- **دسته‌بندی‌های آماده:** قالب وردپرس، قالب HTML، افزونه وردپرس، اسکریپت و کد آماده، نرم‌افزار و ابزار، فایل‌های طراحی (PSD/Figma)، محصولات مجازی (گیفت کارت، لایسنس، اشتراک)
- **مدل محصول دیجیتال:** نوع محصول (قالب/افزونه/اسکریپت/نرم‌افزار/فایل طراحی/مجازی)، نوع لایسنس (تک‌کاربره، چندکاربردی، دائمی، اشتراک، GPL)، دانلود نامحدود یا موجودی محدود، لینک دمو و مستندات، پیش‌نیازها، مدت پشتیبانی و به‌روزرسانی
- **فیلترهای حرفه‌ای:** قیمت (اسلایدر)، نوع محصول، برند/سازنده، فقط دانلود آنی
- **صفحه محصول دیجیتال:** مشخصات فایل (فرمت، حجم، نسخه)، تغییرات نسخه (changelog)، پیش‌نمایش دمو، دانلود مستقیم برای خریدار

`خرید و پرداخت`
- سبد خرید دیجیتال (بدون هزینه ارسال) + کد تخفیف (درصدی/مبلغ ثابت با سقف و حداقل سفارش)
- درگاه‌های زرین‌پال، اسنپ‌پی و ترب‌پی؛ کلیدها فقط از متغیر محیطی خوانده می‌شوند
- **تحویل آنی:** بلافاصله پس از پرداخت موفق، لینک دانلود اختصاصی هر فایل فعال می‌شود

`سیستم دانلود امن`
- برای هر فایل خریداری‌شده یک **توکن دانلود** ساخته می‌شود (۷ روز اعتبار، حداکثر ۵ دانلود)
- دانلود فقط برای مالک توکن ممکن است و شمارش دانلود خودکار انجام می‌شود
- فایل‌های فروشی جدید در `PRIVATE_MEDIA_ROOT` خارج از media عمومی ذخیره می‌شوند؛ راهنمای انتقال فایل‌های قبلی در `deploy/shared-hosting/README.md` است.
- **آپلود یا لینک دانلود:** در فرم محصول، بخش «فایل محصول» دو حالت دارد: «آپلود فایل روی سایت» یا «لینک دانلود» (فایل روی سرور دانلود/هاست دیگر؛ مناسب فایل‌های حجیم). فقط فیلدهای همان حالت نمایش داده می‌شوند؛ حجم فایل لینک‌شده را می‌توان دستی (مگابایت) وارد کرد و فرمت از پسوند لینک خوانده می‌شود.
- لینک دانلود هیچ‌جا در صفحه‌ها چاپ نمی‌شود: خریدار فقط از مسیر `/downloads/<token>/` و **پس از همهٔ بررسی‌ها** (مالکیت، انقضا، سقف دانلود، لغو/استرداد سفارش) به آن هدایت می‌شود (`302` با `Referrer-Policy: no-referrer`). فقط لینک‌های `http/https` پذیرفته می‌شوند. توجه: خریدار آدرس نهایی لینک را می‌بیند؛ برای محافظت بیشتر از لینک‌های تاریخ‌دار هاست دانلود استفاده کنید یا فایل را آپلود کنید.
- اگر فایل آپلودشده روی دیسک نباشد، به‌جای خطای ۵۰۰ پیام روشن نمایش داده می‌شود، از سهمیهٔ دانلود خریدار کم نمی‌شود و اعلان «فوری» برای مدیر ثبت می‌شود. «سلامت فروشگاه» محصولات منتشرشده‌ای را که فایل یا لینک خالی دارند هم نشان می‌دهد.
- بخش **«دانلودهای من»** در پنل کاربری با نمایش باقی‌مانده دانلود و تاریخ انقضا

`بخش طراحی وب سایت (/services/)`
- تعرفه‌های پکیج‌بندی‌شده (سایت شرکتی، فروشگاهی، شخصی، پرتال سازمانی) با امکانات و مدت تحویل
- مراحل انجام پروژه، تکنولوژی‌ها و **نمونه کارها**
- فرم **درخواست مشاوره/سفارش طراحی** (Ajax) و مدیریت درخواست‌ها در پنل مدیریت

`پنل کاربری`
- داشبورد، دانلودهای من، سفارشات و جزئیات سفارش (فاکتور)، لیست علاقه‌مندی، اعلان‌ها، پروفایل و تغییر رمز

`حساب کاربری و امنیت`

## 💳 تنظیم درگاه‌های پرداخت از پنل مدیریت

درگاه‌های پرداخت **بدون نیاز به تغییر کد یا فایل محیطی** از خود سایت قابل تنظیم هستند:

مسیر: پنل مدیریت → «تنظیمات درگاه‌های پرداخت» (یا `/admin/payments/gatewaysettings/`)

| درگاه | نوع | اطلاعات لازم | آدرس بازگشت (Callback) |
|---|---|---|---|
| **زرین‌پال** | پرداخت مستقیم | مرچنت کد؛ حالت سندباکس دارد | `/payments/callback/` |
| **زرین‌پلاس** | خرید اقساطی زرین‌پال | «توکن پذیرنده» در فیلد مرچنت کد/توکن | `/payments/callback/zarinplus/` |
| **اسنپ‌پی** | خرید اقساطی | Client ID، Client Secret، نام کاربری و رمز API، **آدرس پایهٔ API** (از اسنپ‌پی) | `/payments/callback/snappay/` |
| **ترب‌پی** | خرید اعتباری/اقساطی | Client ID، Client Secret، نام کاربری و رمز API (پیش‌فرض آدرس: `https://cpg.torobpay.com`) | `/payments/callback/torobpay/` |

- فقط درگاه‌های **فعال** در صفحهٔ پرداخت نمایش داده می‌شوند. اگر اطلاعات اتصال درگاه فعالی کامل نباشد، برای مشتری با برچسب «موقتاً در دسترس نیست» غیرقابل‌انتخاب است و مدیر (وقتی وارد شده) در همان صفحه هشدارِ «اطلاعات اتصال کامل نیست» را می‌بیند.
- صفحهٔ پرداخت لوگوی رسمی هر درگاه را نشان می‌دهد (`static/img/payments/`، منبع و مجوز در `LICENSE.md` همان پوشه).
- اسنپ‌پی و ترب‌پی برای ساخت طرح اقساط **شماره موبایل** مشتری را لازم دارند؛ اگر در پروفایل نباشد، در صفحهٔ پرداخت پرسیده و در پروفایل ذخیره می‌شود.
- اسنپ‌پی: IP سرور و آدرس بازگشت دقیقاً باید نزد اسنپ‌پی ثبت شود؛ با تیک «حالت تست» و خالی گذاشتن آدرس API، سرور staging اسنپ‌پی استفاده می‌شود. شرایط اقساط (مثلاً «۴ قسط بدون بهره») از API همان درگاه خوانده و زیر گزینهٔ پرداخت نمایش داده می‌شود.
- بازگشت از اسنپ‌پی/ترب‌پی یک POST بین‌سایتی است؛ پرداخت فقط با تأیید سمت سرور (verify + settle) نهایی می‌شود، تکرار بازگشت بی‌اثر است و در قطعی شبکه وضعیت با `status` بازیابی می‌شود.
- رمزها (Client Secret و رمز API) در فرم مدیریت دوباره نمایش داده نمی‌شوند؛ خالی گذاشتن فیلد = حفظ مقدار قبلی.
- اگر فیلدی خالی باشد از متغیر محیطی متناظر خوانده می‌شود (جدول «تنظیمات محیطی»).
- **مهم:** آداپترهای زرین‌پلاس، اسنپ‌پی و ترب‌پی بر اساس مستند رسمی زرین‌پلاس و طراحی API نسخهٔ ۲ اسنپ‌پی/ترب‌پی نوشته و با پاسخ‌های شبیه‌سازی‌شده تست شده‌اند؛ پیش از فعال‌سازی عملیاتی، یک خرید آزمایشی با حساب پذیرندهٔ واقعی (یا staging اسنپ‌پی) انجام دهید.

## 🔔 اعلان‌ها، ایمیل (SMTP) و پیامک (sms.ir)

- **اعلان‌های مدیریت:** سفارش پرداخت‌شده، درخواست طراحی سایت/مشاوره، پیام «تماس با ما»، دیدگاه در انتظار تأیید، ثبت‌نام کاربر و پرداختِ تحویل‌نشده در زنگولهٔ بالای پنل مدیریت نمایش داده می‌شوند (هر ۶۰ ثانیه به‌روز می‌شود). فهرست کامل: `/admin/notifications/adminnotification/`.
- **ایمیل هاست (SMTP):** «اعلان‌ها، ایمیل و پیامک → تنظیمات ایمیل (SMTP)». آدرس سرور، پورت، رمزنگاری (TLS/SSL)، نام کاربری و رمز ایمیل را از پنل هاست وارد کنید و با فیلد «ارسال ایمیل آزمایشی به» اتصال را بسنجید. همین تنظیمات برای بازیابی رمز عبور، خبرنامه و ایمیل اعلان مدیران استفاده می‌شود؛ اگر غیرفعال باشد تنظیمات `.env` (`EMAIL_*`) به کار می‌رود.
- **پیامک sms.ir:** «تنظیمات پیامک (sms.ir)». کلید API (برای آزمایش کلید سندباکس)، شناسهٔ قالب کد تأیید (قالب «ارسال سریع» با متغیر `CODE`؛ در سندباکس `123456`)، شمارهٔ خط (برای پیامک متنی اعلان مدیر)، موبایل مدیران و رویدادهایی که پیامک بفرستند. با فیلد «ارسال کد آزمایشی» اتصال را بسنجید.
- **ورود و ثبت‌نام با موبایل:** با فعال کردن «ورود و ثبت‌نام با کد پیامکی»، گزینهٔ «ورود با شماره موبایل» در صفحهٔ ورود و ثبت‌نام ظاهر می‌شود (`/account/otp/`). کد یک‌بارمصرف فقط به صورت هش ذخیره می‌شود، ۵ بار تلاش و اعتبار کوتاه دارد و ارسال آن برای هر شماره و هر IP محدود است. شمارهٔ ناشناخته یک حساب جدید (بدون رمز) می‌سازد.

## 🧑‍💼 نقش فروشنده و نویسنده

فیلد «فروشنده»ی محصول فقط مدیران و اعضای گروه **«فروشندگان»** و فیلد «نویسنده»ی مقاله فقط مدیران و اعضای گروه **«نویسندگان»** را نشان می‌دهد. نقش را از «کاربران» با اکشن «دادن نقش فروشنده/نویسنده» یا بخش «گروه‌ها»ی صفحهٔ کاربر بدهید. فروشندگان و نویسندگان فعلی هنگام مایگریشن خودکار به این گروه‌ها اضافه شده‌اند.

## 🧱 ساخت صفحه و بخش سفارشی با کد HTML

- **صفحات** (`/admin/pages/staticpage/`): چهار چیدمان «استاندارد با منوی کناری»، «تمام‌عرض»، «متن باریک» و «لندینگ (بدون سربرگ و کادر)». پیش‌نویس‌ها برای مدیر قابل پیش‌نمایش‌اند (لینک «پیش‌نمایش» در همان فرم).
- **کد HTML سفارشی** برای محصول، مقاله و صفحه: ویرایشگر کد با پیش‌نمایش زندهٔ دسکتاپ/تبلت/موبایل؛ نمایش پیش از محتوا، پس از آن یا جایگزین کامل آن.
- **بلوک‌های کد HTML** (`/admin/core/htmlblock/`): بخش دلخواه در بالای/پایین همهٔ صفحات، چند جای صفحهٔ اصلی، زیر همهٔ محصولات/مقاله‌ها و بالای سبد خرید.
- چون کد عیناً اجرا می‌شود، فقط **مدیر کل** یا کاربری که مجوز «ویرایش کد HTML خام» دارد آن را تغییر می‌دهد؛ پیش‌نمایش در iframe ایزوله اجرا می‌شود.
- **برای توسعه‌دهنده:** Django Admin متن راهنما (`help_text`) و توضیح fieldsetها را HTML خام چاپ می‌کند؛ نوشتن خودِ تگ (مثل `<style>`) در آن‌ها یک تگ واقعی باز می‌کرد و بقیهٔ فرم (بخش فایل‌ها، تصاویر و دکمه‌های ذخیره) نامرئی می‌شد. نام تگ را بدون `< >` بنویسید؛ تست `core.tests_admin_html` این را برای همهٔ مدل‌ها و فرم‌های ادمین بررسی می‌کند.

## 🏠 صفحهٔ اصلی: بنرها و ویترین‌ها

- **بنرها:** ارتفاع نمایش (خودکار/کوتاه/متوسط/بلند/خیلی بلند)، عرض (تمام/نصف/یک‌سوم/یک‌چهارم)، تصویر جداگانهٔ موبایل، متن کوچک، متن بنر، متن دکمه، جای متن و رنگ متن، باز شدن در تب جدید، ترتیب نمایش، و لینک داخلی (مثل `/products/`) یا بدون لینک.
- **ویترین‌ها** (`/admin/product/productshowcase/`): محصولات اسلایدر بزرگ «پیشنهادهای ویژه»، اسلایدر کوچک کنار آن (`#bid-s`)، ردیف تخفیف‌ها و پرفروش‌ها را دستی انتخاب و مرتب کنید یا حالت خودکار (جدیدترین/پربازدید/پرفروش/بیشترین تخفیف/ویژه) بگذارید؛ عنوان، زمان هر اسلاید و «پایان نمایش» با شمارش معکوس هم دارد.
- **مگامنوی «دسته‌بندی فایل‌ها»:** آیکن، توضیح کوتاه، ترتیب و نمایش هر دسته از «دسته بندی ها» تنظیم می‌شود؛ پرفروش‌ترین فایل‌های هر دسته خودکار نمایش داده می‌شوند.
- اسلایدر کوچک کنار پیشنهادها (`#bid-s`) در تبلت و موبایل هم دیده می‌شود (یک ردیف تمام‌عرض ۲ تا ۴ محصولی)؛ قالب قبلاً کل این ستون را زیر ۱۰۷۸ پیکسل پنهان می‌کرد.
- وقتی با حساب مدیر وارد شده‌اید، روی اسلایدر، ویترین‌ها و ردیف‌های بنر صفحهٔ اصلی دکمهٔ «تنظیم این بخش» دیده می‌شود که مستقیم صفحهٔ تنظیم همان بخش را باز می‌کند (فقط برای کارمندِ دارای مجوز تغییر همان بخش؛ مشتری‌ها آن را نمی‌بینند).

## 🔍 سئو (SEO) و بهینه‌سازی هوش مصنوعی (GEO)

### اسکیمای ساخت‌یافته (JSON-LD) — خودکار در همه صفحات

| صفحه | اسکیماها |
|---|---|
| همه صفحات عمومی | `Organization` (تماس، شبکه‌های اجتماعی) + `WebSite` (با SearchAction) + `WebPage` خودکار؛ مسیرهای `noindex` هیچ schema عمومی دریافت نمی‌کنند |
| صفحه محصول | `ItemPage` خودکار + `Product` (قیمت IRR، موجودی، برند، دسته، SKU، تصویر) + `BreadcrumbList` |
| فروشگاه / دسته / برند | `CollectionPage` خودکار + `ItemList` (فقط صفحه اول) + `BreadcrumbList` |
| مقاله وبلاگ | `ItemPage` خودکار + `BlogPosting` (نویسنده، ناشر، تاریخ انتشار/به‌روزرسانی، تصویر) + `BreadcrumbList` |
| فهرست وبلاگ | `CollectionPage` خودکار + `ItemList` مقاله‌ها (فقط صفحه اول) + `BreadcrumbList` |
| سوالات متداول | `FAQPage` — **استخراج خودکار پرسش/پاسخ از محتوا** |
| تماس با ما | `ContactPage` + `ContactPoint` |
| خدمات طراحی وب | `Service` + `OfferCatalog` (تعرفه‌ها) |

### متاتگ‌های خودکار

- **Canonical**: خودکار از مسیر جاری (بدون کوئری اضافه؛ صفحات ۲ به بعد با `?page=N`)
- **Robots meta**: صفحات خصوصی (پنل، سبد، پرداخت، ورود، نتایج جست‌وجو) خودکار `noindex, follow`
- **Open Graph + Twitter Card**: og:title/description/image/type در همه صفحات؛ تصویر محصول/مقاله خودکار + تصویر پیش‌فرض اختصاصی
- **کد تأیید Search Console / Bing**: از پنل مدیریت → تنظیمات سایت → بخش سئو

### H1 و alt

- هر صفحه دقیقاً یک `H1` معنادار (محصول/مقاله/دسته/...) دارد
- همه تگ‌های `<img>` دارای `alt` توصیفی فارسی هستند

### نقشه سایت (sitemap.xml)

- همه بخش‌ها: صفحات اصلی (۷)، محصولات، دسته‌ها، برندها، مقالات، صفحات ثابت
- `lastmod` واقعی (تاریخ به‌روزرسانی هر آیتم) + **پلاس تصاویر** (Google Image Sitemap)
- بدون URL تکراری؛ معتبر XML

### robots.txt — با بخش اختصاصی ربات‌های هوش مصنوعی

- قانون عمومی: محتوای عمومی آزاد؛ بخش‌های خصوصی (admin، پنل کاربری، پرداخت، دانلود، سبد) مسدود
- موتورهای جست‌وجو: Googlebot، Bingbot، DuckDuckBot، Yandex
- **ربات‌های AI** (۲۱ User-agent): GPTBot، OAI-SearchBot، ChatGPT-User، ClaudeBot، Claude-Web، PerplexityBot، Google-Extended (Gemini)، Applebot، Amazonbot، cohere-ai، meta-externalagent و... — دسترسی آزاد به محتوای عمومی برای دیده‌شدن در پاسخ‌های هوش مصنوعی

### llms.txt — راهنمای محتوا برای مدل‌های زبانی (استاندارد llmstxt.org)

در آدرس `/llms.txt` فایل مارک‌داونی به‌صورت **داینامیک** تولید می‌شود: معرفی سایت، بخش‌ها، دسته‌بندی‌های فروشگاه و وبلاگ (با شمارش محتوای منتشرشده)، پرفروش‌ترین فایل‌ها **با قیمت**، جدیدترین مقالات، تعرفه‌ها (بستهٔ بدون قیمت: «توافقی») و نکات پاسخ‌دهی — تا دستیارهای هوش مصنوعی محتوای سایت را دقیق درک و ارجاع دهند. همهٔ لینک‌ها **مطلق** (با دامنهٔ سایت) هستند تا خزنده‌های هوش مصنوعی مستقیم از آن‌ها استفاده کنند؛ دسته‌های خالی در فایل نمی‌آیند تا نقشهٔ سایت همیشه واقعی بماند.

## ✨ به‌روزرسانی ۲۰۲۶ — ظاهر و امکانات مدرن ایرانی

### فونت وزیرمتن (Vazirmatn) با ارقام فارسی
- جایگزین فونت قدیمی vazir با **Vazirmatn FD** (نسخه ۲۰۲۶، ۶ وزن، فرمت woff2 سبک ~۵۰KB)
- **همه اعداد سایت به‌صورت خودکار فارسی** نمایش داده می‌شوند (قیمت‌ها، تاریخ‌ها، آمارها)
- بارگذاری با `font-display: swap` + `preload` برای سرعت بالا

### حالت شب/روز (Dark Mode)
- دکمه تغییر حالت در هدر دسکتاپ و موبایل (`aria-pressed` برای صفحه‌خوان‌ها)؛ حالت روز پیش‌فرض فروشگاه است و فقط انتخاب صریح کاربر در `localStorage` (`fm-theme`) ذخیره می‌شود. Django Admin در حالت «خودکار» از تم سیستم پیروی می‌کند (کلاس `fm-auto-dark`).
- اسکریپت ضد فلش (Anti-FOUC): صفحه قبل از رندر حالت درست را می‌گیرد؛ صفحهٔ آفلاین و صفحهٔ اضطراری خطای ۵۰۰ هم همین کلید را می‌خوانند.
- همگام‌سازی `theme-color` مرورگر
- **قاعدهٔ توکن‌ها:** در حالت شب طیف فیروزه‌ای وارونه می‌شود؛ `--fm-primary-700` رنگ «متن» است (در شب روشن) و `--fm-action-bg` رنگ «زمینهٔ دکمه» (در هر دو حالت تیره). پس‌زمینهٔ دکمه با متن سفید را هرگز با primary-700 نسازید و برعکس.
- اصلاحات اجزای قالب قدیمی که رنگ سفید/روشنِ ثابت دارند در `static/css/fm-dark.css` (آخرین برگهٔ سبک) هستند و همه زیر `[data-theme="dark"]`؛ تست `core.tests_dark_mode` اجازه نمی‌دهد قاعده‌ای از این فایل حالت روز را تغییر دهد.
- لوگو در حالت شب روی کادر روشن نمایش داده می‌شود، مگر «لوگوی حالت شب» در تنظیمات سایت آپلود شده باشد.

### جست‌وجوی زنده (Live Search)
- تایپ در جست‌وجو → پیشنهاد لحظه‌ای محصولات با **عکس، دسته و قیمت فارسی**
- فقط با درخواست AJAX جواب JSON می‌دهد (امنیتی)؛ نتایج محدود به ۶ آیتم + لینک همه نتایج

### خبرنامه
- فرم عضویت در فوتر همه صفحات (AJAX + پیام فارسی + اعتبارسنجی ایمیل + محافظت CSRF)
- مدیریت مشترکان از پنل: `/admin/core/newslettersubscriber/`

### پولیش مدرن ۲۰۲۶ (تمام صفحات)
- هدر شیشه‌ای چسبان (backdrop-filter) + کارت‌های گوشه‌گرد با سایه لایه‌ای
- دکمه‌های گرادیانی فیروزه‌ای با انیمیشن هاور
- دکمه **بازگشت به بالا با حلقه پیشرفت مطالعه**
- اسکرول‌بار سفارشی، انیمیشن ورود نرم بخش‌ها، focus-ring دسترس‌پذیری
- عنوان بخش‌ها با زیرخط گرادیانی + هاور بلندشدن کارت محصول
- احترام به `prefers-reduced-motion` (کاربران حساس به انیمیشن)

### PWA و موبایل
- `/manifest.webmanifest` (پویا، از **تنظیمات سایت**) با هویت فارسی (fa-IR، RTL)، نام و آیکن فعلی سایت و shortcutهای «فایل‌ها»، «تخفیف‌ها» و «دانلودها»
- service worker با scope ریشه و ثبت graceful در مرورگرهای امن؛ فقط shell عمومی/static cache می‌شود
- navigationها همیشه network-first هستند و در نبود اینترنت به `/offline/` می‌رسند؛ checkout، پرداخت، دانلود، سبد خرید و dashboard هرگز cache نمی‌شوند
- آدرس فایل‌های CSS/JS پروژه یک نسخهٔ محتوایی دارد (`?v=<hash>`)؛ بعد از هر استقرار، مرورگر و service worker فایل تغییرکرده را از همان اولین بازدید تازه می‌گیرند (قبلاً نسخهٔ قدیمی از کش اجرا می‌شد و سبد خرید/منو گاهی با صفحهٔ جدید ناهماهنگ بود). برای افزودن CSS/JS در قالب‌ها به‌جای `{% static %}` از `{% asset '…' %}` (کتابخانهٔ `site_extras`) استفاده کنید؛ نیازی به تغییر تنظیمات وب‌سرور نیست.
- رفع باگ فرم جست‌وجوی موبایل (به سرچ واقعی وصل شد)
- سال شمسی خودکار در کپی‌رایت فوتر

### منوی همبرگری و منوی کناری صفحه‌ها در موبایل
- **منوی اصلی موبایل** (زیر ۱۰۷۸px): کشوی سمت راست با کارت حساب کاربری (دانلودها، سفارش‌ها، علاقه‌مندی‌ها، سبد خرید؛ و برای مدیر «پنل مدیریت فروشگاه»)، بخش‌های «فروشگاه / خدمات طراحی سایت / راهنما و ارتباط با ما»، کلید «حالت شب»، تماس تلفنی با پشتیبانی (شمارهٔ اول تنظیمات سایت) و شبکه‌های اجتماعی.
- **منوی کناری همهٔ صفحه‌ها** زیر ۹۹۲px به‌جای اینکه بالای محتوا بیاید، کشوی همبرگری است و یک دکمهٔ «☰» بالای محتوا بازش می‌کند: فیلترهای فروشگاه (همه فایل‌ها، دسته، برند، تخفیف‌ها، جست‌وجو — دکمه با اسکرول زیر هدر می‌ماند، تعداد نتیجه و نشان تعداد فیلترهای فعال دارد و «اعمال فیلتر» پایین کشو ثابت است)، منوی پنل کاربری، دسته‌ها و آخرین مقالات وبلاگ، و «صفحات راهنما». در دسکتاپ همان ستون کناری قبلی است.
- پنل `/admin-panel/` و Django Admin هم همین رفتار را دارند: در Django Admin زیر ۷۶۸px دکمهٔ «منو» در سربرگ کشوی دسترسی سریع + همهٔ بخش‌ها را باز می‌کند و در فهرست‌ها (محصولات، سفارش‌ها، دیدگاه‌ها و …) دکمهٔ «فیلترها» بالای جدول، پنل فیلتر را که قبلاً زیر جدول بود به‌صورت کشو باز می‌کند (با نشان «فعال» وقتی فیلتری اعمال شده). انتخاب صریح تم «روز» در ادمین هم حالا همان پالت پیش‌فرض فروشگاه را دارد (قبلاً سربرگ آبی پیش‌فرض جنگو می‌شد).
- رفتار مشترک همهٔ کشوها: پس‌زمینهٔ تیره، دکمهٔ بستن، کلید Esc، کشیدن انگشت به سمت راست برای بستن، قفل اسکرول صفحه، نگه‌داشتن فوکوس داخل منو و برگرداندن آن به دکمه. کنترلر مشترک: `static/js/fm-drawers.js`؛ ظاهر: `static/css/fm-drawers.css`. بدون JS ستون‌های کناری مثل قبل در صفحه می‌مانند.
- **افزودن منوی کناری کشویی به صفحهٔ جدید:** داخل همان `.row`، پیش از ستون کناری
  `{% include 'includes/side_drawer_toggle.html' with target='my-side' label='عنوان دکمه' hint='توضیح کوتاه' %}`
  و روی خود ستون `id="my-side" class="… fm-side" data-fm-drawer data-fm-drawer-media="(max-width: 991.98px)" aria-labelledby="my-side-title"` و اولین فرزند آن
  `{% include 'includes/side_drawer_head.html' with target='my-side' title='عنوان کشو' icon='fa-bars' %}`.

## 🎨 تغییر نام، لوگو و آیکن تب سایت

همه‌چیز از یک جا: **Django Admin ← اپ اصلی ← تنظیمات سایت ← «هویت سایت»** (فقط یک ردیف تنظیمات وجود دارد؛ لیست مستقیم همان را باز می‌کند و دکمهٔ «افزودن» ردیف دوم نمی‌سازد).

| فیلد | کجا اعمال می‌شود |
|---|---|
| **نام سایت** | عنوان تب و هدر فروشگاه و پنل کاربری، سربرگ/عنوان تب/فوتر Django Admin و صفحهٔ ورود آن، پنل مدیریت `/admin-panel/`، صفحهٔ آفلاین، نام اپ نصب‌شده (PWA)، اسکیمای سئو، `llms.txt` و ایمیل بازیابی رمز |
| **لوگو** | هدر فروشگاه (دسکتاپ و منوی موبایل)، کنار نام در Django Admin و پنل مدیریت، لوگوی اسکیمای سئو؛ اگر «آیکن تب» خالی باشد آیکن‌ها هم از لوگو ساخته می‌شوند |
| **لوگوی حالت شب (اختیاری)** | هدر فروشگاه در حالت شب (نسخهٔ روشنِ لوگو، مثلاً متن سفید با پس‌زمینهٔ شفاف). اگر خالی باشد لوگوی اصلی در شب روی کادر روشن نمایش داده می‌شود |
| **آیکن تب مرورگر (فاوآیکن)** | آیکن تب در همهٔ صفحه‌ها (فروشگاه، پنل کاربری، ادمین، پنل مدیریت)، `/favicon.ico`، آیکن صفحهٔ اصلی آیفون و آیکن نصب اپ (PWA). بهترین نتیجه: تصویر **مربعی** PNG حداقل ۵۱۲×۵۱۲ با پس‌زمینهٔ شفاف |

- آیکن‌ها در اندازه‌های ۳۲، ۱۸۰، ۱۹۲ و ۵۱۲ از `/brand/icon-<size>.png` ساخته می‌شوند (کل تصویر در مربع جا می‌گیرد، بریده نمی‌شود) و پیش‌نمایششان زیر همان فیلدها دیده می‌شود. اگر نه فاوآیکن آپلود شده باشد نه لوگو، آیکن‌های پیش‌فرض `static/` استفاده می‌شوند.
- آدرس لوگو و آیکن‌ها با هر ذخیره نسخهٔ تازه (`?v=…`) می‌گیرد تا مرورگر تصویر قبلی را از کش نشان ندهد. با این حال مرورگرها فاوآیکن را سخت کش می‌کنند: اگر بلافاصله عوض نشد یک‌بار Ctrl+F5 بزنید. (`/favicon.ico` قبلاً ریدایرکت دائمی ۳۰۱ داشت؛ مرورگری که آن را کش کرده ممکن است تا پاک‌شدن کش، آیکن قدیمی را برای آن آدرس نگه دارد.)
- گزینهٔ **«جایگزینی نام قبلی در متن‌ها»** (پیش‌فرض روشن): هنگام ذخیره، نام قبلی (و نام پیش‌فرض «فایل‌مارکت») را در شعار، عنوان و توضیحات سئو، متن فوتر، کپی‌رایت و متن‌های درباره/تماس با نام جدید جایگزین می‌کند. اگر نام قدیمی هنوز در این متن‌ها باشد، صفحهٔ تنظیمات هشدار می‌دهد.
- محتوای محصولات، مقاله‌ها و صفحه‌های ثابت خودکار ویرایش نمی‌شود. نام فرستندهٔ ایمیل‌ها از `DEFAULT_FROM_EMAIL` در `.env` می‌آید. کسانی که اپ (PWA) را قبلاً نصب کرده‌اند برای دیدن نام/آیکن جدید ممکن است لازم باشد اپ را دوباره نصب کنند.

## ↪ مدیریت ریدایرکت‌ها (از پنل)

مسیر: پنل مدیریت → «ریدایرکت‌ها» (`/admin/core/redirect/`)

- **ریدایرکت دستی**: ثبت آدرس قدیمی → جدید با انتخاب کد ۳۰۱ (دائمی، مناسب سئو) یا ۳۰۲ (موقت) + فعال/غیرفعال + شمارش دفعات استفاده
- **ریدایرکت خودکار**: با تغییر نامک (slug) هر **محصول، مقاله، دسته‌بندی، برند یا صفحه ثابت**، ریدایرکت ۳۰۱ قبلی → جدید به‌صورت خودکار ساخته می‌شود (اعتبار سئو حفظ می‌شود)
- **جلوگیری از حلقه**: اگر نامک به مقدار قبلی برگردد، ریدایرکت معکوس خودکار حذف می‌شود؛ حلقه‌های ریدایرکت هرگز رخ نمی‌دهد
- **پشتیبانی با/بدون اسلش**: `/old-page` و `/old-page/` هر دو کار می‌کنند
- مسیرهای خالی مثل `/products/category/` و `/blog/category/` به صفحه مرتبط هدایت می‌شوند (نه 404)
- زنجیره‌های ریدایرکت (A→B→C) به‌درستی دنبال می‌شوند

## ✅ ران نهایی و تست سلامت

دستور مدیریتی جامع برای اطمینان از سلامت کل سایت (۶۰ درخواست در ۳ نقش + سئو + ریدایرکت + پرداخت + دانلود):

## ⚙️ تنظیمات محیطی

مقادیر را از `.env.example` کپی و تنظیم کنید:

```
SECRET_KEY=...
DEBUG=False
ALLOWED_HOSTS=example.com
CSRF_TRUSTED_ORIGINS=https://example.com

ZARINPAL_MERCHANT_ID=...
ZARINPLUS_MERCHANT_TOKEN=...
SNAPPAY_CLIENT_ID=...
SNAPPAY_CLIENT_SECRET=...
SNAPPAY_USERNAME=...
SNAPPAY_PASSWORD=...
SNAPPAY_BASE_URL=https://...        # از اسنپ‌پی
TOROBPAY_CLIENT_ID=...
TOROBPAY_CLIENT_SECRET=...
TOROBPAY_USERNAME=...
TOROBPAY_PASSWORD=...
# آدرس عمومی سایت برای لینک‌های داخل ایمیل اعلان‌ها
SITE_URL=https://example.com
# ارسال ایمیل/پیامک اعلان در پس‌زمینه (پیش‌فرض 1)
NOTIFICATIONS_ASYNC=1
# فقط برای اجرای نخست seed_demo در production:
SEED_ADMIN_PASSWORD=...
SEED_DEMO_PASSWORD=...

# بهینه‌سازی آپلود تصویر (اختیاری)
IMAGE_OPTIMIZATION_ENABLED=true
IMAGE_OPTIMIZATION_MAX_DIMENSION=2000
IMAGE_OPTIMIZATION_WEBP_QUALITY=82
```

- نام و شعار سایت از **تنظیمات سایت** در پنل ادمین قابل تغییر است (پیش‌فرض: «فایل‌مارکت»)؛ جزئیات در بخش «🎨 تغییر نام، لوگو و آیکن تب سایت».
- **تنظیمات سایت** در پنل ادمین شامل: لوگو (تصویری)، آیکن تب مرورگر (فاوآیکن)، توضیح فوتر، لینک شبکه‌های اجتماعی خارجی (اینستاگرام، تلگرام، واتساپ، X، یوتیوب، لینکدین، فیسبوک، پینترست، گیت‌هاب) و ایرانی (آپارات، ایتا، روبیکا، بله، سروش پلاس، آی‌گپ، ویرگول)، لینک نماد اینماد و ساماندهی (اگر ست نشوند نشان داده نمی‌شوند)، عنوان و توضیحات متای سئو، **کدهای تأیید Google Search Console و Bing**، و تعداد محصول در هر صفحه.
- عناوین و توضیحات متای هر محصول/مقاله از فیلدهای اختصاصی سئو در پنل خوانده می‌شوند و در نبودشان به‌صورت خودکار از محتوا تولید می‌شوند.
- در حالت DEBUG همه هاست‌ها پذیرفته می‌شوند (برای پیش‌نمایش آنلاین)؛ در محیط عملیاتی مقدار `ALLOW_ALL_HOSTS=0` یا `DEBUG=False` قرار دهید.
